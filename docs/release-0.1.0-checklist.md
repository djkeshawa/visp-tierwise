## 2. Criteria in detail

### 1. Spec §4 is specified, and every rule has at least one vector: not yet

- **Spec text:** `spec/spec.md` (terminology and index) and `spec/sections/01`–`13`, with 1,106 normative clauses and stable IDs, written to `spec/AUTHORING.md`. The decisions are in ADRs 0005 and 0007–0017.
- **Vector coverage:** `spec/conformance/COVERAGE.md` (generated by `spec:check`) shows 887 clauses cited by a vector and 219 not cited. Of the 219, 133 have an implemented enforcer listed in `spec/conformance/enforcers.yaml` and `enforcers.d/`, and 86 have an enforcer marked *Planned*, which means the test is not written yet.
- **Header:** `spec/spec.md` still reads "Spec version: 0.1 (draft, not accepted)". `docs/phase-1-review.md` records the acceptance. *(OPEN)* O-6.
- **Needed:** vectors for the 219 uncited clauses, or an owner decision that enforcer-only clauses meet the criterion *(OPEN)* O-4; and the 86 planned tests written.

### 2. Both evaluators pass every evaluator and canonical vector, in both domains: met

- **Java** (`java/tierwise-core`, `-Pconformance`): `EvaluateVectorsTest` 576 of 576, `CanonicalVectorsTest` 32 of 32.
- **JavaScript** (`js/evaluator/test/conformance.test.mjs`): 608 vector subtests (576 evaluate, in eight areas, and 32 canonical) plus the suite entry, 609 of 609 passing.
- **Both domains:** of the 576 evaluate vectors, 22 use `bundles/commerce.json` (domain A), 9 use `bundles/retail-pos.json` (domain B) and 5 use `bundles/saas-entitlements.json`. 526 use the `bundles/edge-*.json` bundles, and 14 use the deliberately invalid bundles. Counted from the `bundle:` reference in each vector file.
- **Caveat:** the vectors were written by hand (`docs/phase-1-review.md`). Both runners agree with them today.

### 3. One night of cross-language differential runs with zero disagreements: not yet

- **One run here:** `scripts/differential.sh --seed 20261009 --cases 10000` wrote 10,000 cases. Java produced them, and JavaScript replayed each one with no difference. 7,567 cases returned a result and 2,433 returned an error code. The run also compared 9,700 listener events.
- **Not met:** `.github/workflows/nightly.yml` (cron 03:17 UTC, 10,000 cases, the run id as the seed) has not run on a hosted runner, and a single run is not a night. *(OPEN)* O-10.

### 4. Every engine error, evaluation error and lint rule is implemented and tested, with an explain entry: met with caveats

- **Codes:** `spec/error-codes.md` lists 59 codes: 51 engine codes (4 of them are also raised by evaluators), 7 evaluation-only codes, and 1 tooling code (`E_PROVENANCE_INVALID`). It also lists 9 lint entries, where `naming/*` is one entry. Every code appears in production source under `java/*/src/main` or `js/*/src`, checked by grep.
- **Golden tests:** all 51 engine codes have a compile case (`spec:check --strict`, stage f). The evaluation codes appear in between 3 and 52 evaluate vectors. `E_PROVENANCE_INVALID` appears in 11 provenance case files. Each lint entry appears in between 2 and 13 compile cases, and `naming/*` has the most (13).
- **Explain:** `tierwise explain <code>` exits 0 for all 59 codes and all 9 lint entries (68 of 68). An unknown code exits 1.
- **Caveat:** the nine Java lint rules each have only one to four unit tests (`java/tierwise-core/src/test/java/io/github/tierwise/core/internal/lint/`), so their golden coverage comes from the compile cases. `spec:check` counts 8 lint identifiers and `error-codes.md` lists 9 entries. The two agree: the check counts the 8 fixed identifiers, and `naming/*` stands for the pattern `naming/<name>` (one per naming pattern), which `spec/schemas/vector-compile.schema.json` accepts by a regular expression instead of listing it.

### 5. No domain term in production code, and the genericity check runs in CI: met with caveats

- **Run:** `pnpm --dir js run genericity` printed "Genericity check passed: 146 names from 3 samples, 388 production files scanned, 21 allow-listed."
- **CI:** `.github/workflows/ci.yml`, job `javascript`, step "Genericity check".
- **Caveat:** the scan is lexical (whole-word matches in identifiers and string literals; `SCAN_COMMENTS` is false in `js/scripts/check-genericity.mjs`). The 21 allow-listed words are in `js/scripts/genericity-allowlist.txt`. A pass is not a semantic audit.

### 6. No modeling choice is hardcoded: met with caveats

- Kinds and naming patterns come from presets and project schema, not from engine code (ADR 0011 §7 and ADR 0013 "Naming patterns"). The engine takes levels, keys, facts and features from the bundle.
- The defaults in code are runtime-integration defaults that §14 sets: refresh every 30 s and staleness at 5 min (`js/node` and `java/tierwise-spring-boot-starter`), and a provider timeout of 200 ms (the starter's default; the core has none, by SVC-48). The S3 modules' own defaults are open in their README *(OPEN)* O-14.
- **Caveat:** this rests on the lexical check and on design review. No semantic audit has been run.

### 10. `/resolve` and `/decide` match in-process results: met with caveats
