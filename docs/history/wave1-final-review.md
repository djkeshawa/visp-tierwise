# Wave 1 final review (2026-10-09)

The main model's cross-section review of spec sections 1–13. ADR 0013 decides every item below; where ADR 0013 says "adopted as recommended", the recommendation text here is normative input.

## Summary

I checked all 13 wave-1 sections and spec/spec.md together, and fixed the problems in place. I ran no git commands.

**Mechanical checks** (run by a script, then rerun after the fixes):
- Clause IDs are unique.
- Each section uses only the areas spec.md gives it.
- No area has a gap in its numbering.
- Every bracketed reference points to a clause that exists.
- Every OPEN clause appears in its section's Open points list. BUNDLE-118 to BUNDLE-136 are listed as a range.

**Stale citations.** About 250 references pointed at a clause that exists but has the wrong meaning. The cause was renumbering in sections 2, 3, 4, 5, 6, 8, 9, 10, 11, 12 and 13. I checked each one against the target clause's text and corrected it. Every sibling-update list in the item outcomes is now applied. I also found and fixed citations those lists missed, for example:
- FACT-6 to FACT-41 and RULE-17 cited old TYPE and NORM numbers.
- Section 11 cited old SVC, PROV, BUNDLE, FACT, BIND and RULE numbers throughout.
- SRC-40 cited FACT-9 instead of FACT-5.
- FIND-23 cited MANIFEST-31 instead of MANIFEST-24.
- LINT-18 cited TYPE-15 instead of TYPE-33.
- SRC-44 cited POL-3 instead of POL-5.

**Circular and broken references:**
- Section 6 sent listener behaviour to section 11, and section 11 sent it back to SVC clauses that are about something else. EVAL-44 now owns it, and section 6 points there.
- EVAL-14 and BUNDLE-117 each deferred the load-check order to the other. EVAL-14 is now the OPEN owner, and it records both proposals, which disagree.
- BUNDLE-116 and EVAL-24 each called the other open. Now only BUNDLE-116 holds the question, and EVAL-24 refers to it.
- EVAL-19, EVAL-30 and EVAL-32 called CTX-5 and CTX-7 open, but both are settled. They now state the settled rule.

**Terminology.** spec.md §Terminology now has about 100 more terms, grouped by section, each pointing to the clause that defines it. This covers every term the sections said was pending. The definition lists in sections 6 and 12 and the definitions paragraph in section 13 moved there. The "until they move" sentences in sections 1, 3 and 5 now point to spec.md. The index title for section 1 is now "Manifest, sources and namespaces".

**Rules stated twice.** Three rules were restated outside their owning section:
- SRC-36 (where a finding about inline content is located) now cites FIND-17 and FIND-19.
- FEAT-7 now defers to TYPE-6 for the shape of the enum list.
- FEAT-8 no longer claims that no rule covers `returns.enum`, because TYPE-6 does.

I found no two clauses that contradict each other. The open points do conflict, though: several items' recommendations disagree on which codes to use (see Remaining, items 1 to 3).

**Error codes.** Every code used normatively is in requirements §6.1 or §6.2, and each one means the same thing everywhere. E_TYPE_DECLARATION and E_PROVENANCE_INVALID appear only as proposals inside OPEN clauses.

**Section 9.** Its item came back as "revise", and its 9 pending edits are not applied. The exact text of those edits was not given to me. The disk now has 34 GB free, so they can be applied once the item notes are supplied.

## Remaining open points and recommendations

- Not done: section 9's item came back 'revise', and its 9 pending edits are still not applied to spec/sections/09-provenance.md. The exact edit text was in the item notes, which I did not receive. The disk now has 34 GB free, so the edits can be applied once the notes are supplied. Edit 9 is the PROV-53 wording.
- Cross-cutting 1, the structural-declaration code. These all ask for a code for a missing, unknown or wrongly shaped member: SRC-16, KEY-5, FEAT-2, FEAT-16, ENTITY-7, FACT-8, TYPE-11, TYPE-22(b), TYPE-52(a), RULE-6, POL-25 and POL-45. The items recommend different new codes (E_TYPE_DECLARATION, E_KEY_DECLARATION, E_CONDITION_SYNTAX, or one generic code). Recommendation: one ADR adds a single code, for example E_INVALID_DECLARATION, for all of them. The existing specific codes keep precedence: E_MANIFEST, E_PRESET, E_SCOPE_DECLARATION, E_KIND_DEFINITION and E_TYPE_REQUIRED.
- Cross-cutting 2, repetition. ENTITY-8, TYPE-52(b) and (c), KEY-7 (repeat), FEAT-8 (repeat), FEAT-21, POL-19, POL-30 and RULE-21 all ask what a repeated entry reports. The item recommendations disagree: S4 says E_TYPE_DECLARATION for a repeated declaration entry, S5 says the KEY-5 code, and S7 says E_DUPLICATE_VALUE. Recommendation: E_DUPLICATE_VALUE for every repeated entry, in a declaration list or in a value. An empty list takes the cross-cutting 1 code. The ADR widens E_DUPLICATE_VALUE beyond the source-conflict meaning it has in ADR 0011 §5.
- Cross-cutting 3, parse and encoding errors (SRC-5, SRC-6, SRC-10, the parse part of SCOPE-30, VEC-6). Recommendation: one new parse code for non-manifest sources and catalog files, and E_MANIFEST for the manifest. Sources are UTF-8 only, and a byte-order mark is rejected.
- Cross-cutting 4, paths that leave the project root (MANIFEST-12, SCOPE-28, SRC-17, and the symlink part of SRC-18). Recommendation: forbid them for every manifest and catalog path, with E_MANIFEST. Resolve symbolic links before the containment check.
- Cross-cutting 5, non-string scalars in name positions (SRC-11, SCOPE-20, the element case of ENTITY-7). Recommendation: use the enclosing declaration's code where one exists, such as E_SCOPE_DECLARATION for a `nodes` list. Otherwise report E_TYPE_MISMATCH with a hint to quote the value. Never convert silently.
